# نظام إدارة مخولين مكتب النائب

تطبيق ويب (PWA) لإدارة المخولين والمهام/الطلبات في مكتب النائب، قابل للتثبيت كأيقونة على الشاشة الرئيسية لأندرويد، آيفون (iOS)، وويندوز.

## المزايا

- تسجيل دخول بحساب مستخدم وكلمة مرور، بأربعة أدوار: **مسؤول رئيسي**، **مخوّل**، **موظف متابعة**، **اطلاع فقط**.
- شاشة رئيسية ببطاقات رئيسية: **المخولين**، **المكاتب**، **الطلبات**، **المتأخرة** + إحصائيات سريعة.
- إدارة المخولين مع إمكانية إضافة صورة لكل شخص، وقائمة **مكاتب مُدارة** (إضافة/تعديل/تعطيل/حذف) تُستخدم كقوائم منسدلة عند إسناد المهام بدل الكتابة اليدوية.
- إضافة مهمة عبر زر "مهام" بنوع من ثلاثة: **مهمة عادية** أو **مهمة عاجلة** (تُسند إلى مخوّل)، أو **متابعة مخول** (تُسند إلى موظف متابعة لمتابعة بريد مخوّل أو مكتب محدد)، مع الحقول: عنوان المهمة، اسم المكتب صاحب الطلب، التاريخ (تاريخ الاستحقاق)، إرفاق ملف، التفاصيل.
- صاحب المهمة (مخوّل أو موظف متابعة) يستطيع تحديد حالة المهمة: **قيد الانجاز** / **منجز** (يُسجَّل تاريخ الإنجاز تلقائياً) / **مرفوض** (مع ذكر السبب)، وإعادة رفع ملف عند إكمال المهمة.
- المهام المتأخرة تُحسب تلقائياً (مهمة "قيد الانجاز" تجاوزت تاريخ استحقاقها).
- كل حساب (بأي دور) يستطيع تغيير كلمة مروره بنفسه من زر "تغيير كلمة المرور"، والمسؤول الرئيسي يملك صلاحية إضافة/تعديل/تعطيل/حذف أي حساب من "إدارة الحسابات".
- تقارير: لكل مخوّل، لكل مكتب، وتقرير عام، مع تصدير Excel حقيقي (.xlsx) بالأعمدة: تسلسل، اسم المخول، اسم المكتب، نوع الطلب، موضوع الطلب، تأريخ اسناد الطلب، تأريخ استلام الطلب، حالة الطلب — مع قوائم منسدلة فعلية داخل الإكسل لأعمدة المخول/المكتب/النوع/الحالة، وفلتر تلقائي على كل الأعمدة.
- حسابات اطلاع فقط (قراءة/تقارير بدون تعديل).
- أرشفة تلقائية لكل مهمة جديدة أو تحديث حالة عبر بوت تلغرام (اختياري).
- قابل للتثبيت كتطبيق (PWA) بأيقونة صورة المكتب على خلفية كحلية (أزرق غامق) مع نقشة هندسية، على أندرويد وآيفون وويندوز.

## التشغيل محلياً

يتطلب تثبيت [Node.js](https://nodejs.org) (الإصدار 18 فأعلى).

```bash
npm install
npm start
```

بعد التشغيل، افتح المتصفح على: `http://localhost:3000`

### الحساب الافتراضي عند أول تشغيل

- اسم المستخدم: `admin`
- كلمة المرور: `admin123`

**مهم جداً:** غيّر كلمة المرور فوراً من داخل التطبيق (زر "تغيير كلمة المرور" أو من صفحة إدارة الحسابات).

## إعداد بوت تلغرام للأرشفة (اختياري)

1. افتح تطبيق تلغرام وابحث عن **BotFather**.
2. أرسل له الأمر `/newbot` واتبع التعليمات لإنشاء بوت جديد، سيعطيك **توكن** (Token) شبيه بـ:
   `123456789:ABCdefGhIJKlmNoPQRstuVwxyZ`
3. أنشئ قناة أو مجموعة تلغرام خاصة بالأرشيف، وأضف البوت إليها كمشرف (Admin).
4. للحصول على **معرّف المحادثة** (Chat ID):
   - إذا كانت قناة: انشر أي رسالة فيها ثم افتح
     `https://api.telegram.org/bot<التوكن>/getUpdates` في المتصفح، وابحث عن `"chat":{"id":...}` — عادة يبدأ برقم سالب مثل `-1001234567890`.
   - أو استخدم بوت مساعد مثل `@userinfobot` / `@getidsbot` للحصول على المعرف مباشرة.
5. انسخ ملف `.env.example` إلى `.env` وعبّئ القيم:

```
TELEGRAM_BOT_TOKEN=التوكن_هنا
TELEGRAM_CHAT_ID=معرف_المحادثة_هنا
```

6. أعد تشغيل الخادم. من الآن، كل مهمة جديدة أو تحديث حالة (منجز/مرفوض/قيد الانجاز) سيُرسَل تلقائياً كنسخة أرشيفية إلى القناة.

> إذا تُركت هذه المتغيرات فارغة، يعمل التطبيق بشكل طبيعي بدون الأرشفة على تلغرام.

## النشر على الإنترنت (حتى يصبح رابطاً حقيقياً يمكن تثبيته من الهاتف)

التطبيق مبني الآن للعمل على استضافة **Vercel** (لا-خادمية) مع قاعدة بيانات سحابية
**Turso** — كلا الحسابين مجانيان بالكامل بدون أي بطاقة بنكية. لذلك يستخدم
التطبيق قاعدة بيانات سحابية بدل ملف SQLite محلي، وتُخزَّن الملفات المرفوعة
(الصور والمرفقات) داخل قاعدة البيانات نفسها بدل القرص، لأن Vercel لا يوفر قرصاً
دائماً بين الطلبات.

### الخطوة 1: إنشاء قاعدة بيانات على Turso (مجاني، بدون بطاقة)

1. افتح [turso.tech](https://turso.tech) وسجّل الدخول بحساب GitHub.
2. من لوحة التحكم أنشئ قاعدة بيانات جديدة (Create Database)، واختر أقرب موقع خادم.
3. بعد إنشائها، ابحث عن رابط الاتصال (يبدأ بـ `libsql://...`) وتوكن الوصول
   (Auth Token / Create Token) — قد تجدهما مباشرة في لوحة التحكم، أو عبر تبويب
   "Connect" الخاص بقاعدة البيانات.
4. احتفظ بهذين القيمتين (الرابط والتوكن) لاستخدامهما في الخطوة التالية.

### الخطوة 2: رفع المشروع إلى GitHub

ارفع مجلد المشروع كاملاً (بدون `node_modules`) إلى مستودع على GitHub، كما فعلت
سابقاً.

### الخطوة 3: النشر على Vercel (مجاني، بدون بطاقة)

1. افتح [vercel.com](https://vercel.com) وسجّل الدخول بحساب GitHub.
2. اضغط **Add New → Project**، واختر المستودع الذي رفعت إليه المشروع، ثم **Import**.
3. في صفحة إعدادات المشروع قبل الضغط على Deploy، افتح **Environment Variables** وأضف:
   - `SESSION_SECRET` — نص عشوائي طويل وخاص.
   - `TURSO_DATABASE_URL` — الرابط الذي حصلت عليه من Turso.
   - `TURSO_AUTH_TOKEN` — التوكن الذي حصلت عليه من Turso.
   - (اختياري) `TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID` للأرشفة على تلغرام.
4. اضغط **Deploy**. خلال دقيقة أو أقل سيعطيك Vercel رابط HTTPS دائم (مثل
   `https://your-app.vercel.app`) — هذا الرابط هو ما يفتحه المخولون ويثبّتونه
   على هواتفهم وأجهزتهم.
5. أي تحديث لاحق على الكود في مستودع GitHub سينشر تلقائياً نسخة جديدة على نفس الرابط.

> ملاحظة: أول تشغيل للتطبيق بعد الربط بقاعدة بيانات Turso فارغة سيُنشئ تلقائياً
> الحساب الرئيسي الافتراضي (`admin` / `admin123`) والمكاتب الافتراضية — تماماً
> كما يحدث عند التشغيل المحلي لأول مرة.

## تثبيت التطبيق كأيقونة على الهاتف/الويندوز

بعد نشر التطبيق والحصول على رابط HTTPS:

- **أندرويد (Chrome):** افتح الرابط، اضغط على قائمة المتصفح (⋮) ثم "إضافة إلى الشاشة الرئيسية" / "تثبيت التطبيق".
- **آيفون (Safari):** افتح الرابط، اضغط على زر المشاركة (Share) ثم "إضافة إلى الشاشة الرئيسية".
- **ويندوز (Chrome/Edge):** افتح الرابط، ستظهر أيقونة تثبيت (⊕) في شريط العنوان، اضغط عليها لتثبيت التطبيق كبرنامج مستقل بأيقونته الخاصة.

في كل الحالات ستظهر أيقونة التطبيق باللون التركوازي المُعد في هذا المشروع.

## هيكل المشروع

```
office-agents-app/
├── server/
│   ├── index.js        # الخادم الرئيسي وكل مسارات الـ API
│   ├── db.js            # الاتصال بقاعدة بيانات Turso/libSQL وتهيئة الجداول
│   ├── auth.js           # تسجيل الدخول عبر JWT في كوكي httpOnly والتحقق من الصلاحيات
│   └── telegram.js       # إرسال الأرشيف إلى بوت تلغرام
├── public/
│   ├── index.html         # واجهة التطبيق (شاشة واحدة SPA)
│   ├── app.js              # منطق الواجهة الأمامية
│   ├── styles.css           # التنسيقات (الثيم الكحلي)
│   ├── manifest.json         # إعدادات PWA
│   ├── service-worker.js      # لتفعيل التثبيت والعمل الجزئي دون اتصال
│   └── icons/                  # أيقونات التطبيق بمقاسات مختلفة
├── assets/icon.svg                # مصدر الأيقونة
├── vercel.json                     # إعدادات النشر على Vercel
├── data/app.db (محلياً فقط، يُنشأ تلقائياً عند عدم ضبط TURSO_DATABASE_URL)
├── .env.example
└── package.json
```

> ملاحظة: الملفات المرفوعة (صور المخولين ومرفقات المهام) لم تعد تُخزَّن كملفات
> على القرص، بل داخل جدول `files` في قاعدة البيانات نفسها، وتُخدَّم عبر المسار
> `/api/files/:id` — وذلك ليعمل التطبيق بشكل صحيح على استضافة Vercel اللا-خادمية.

## ملاحظات أمنية قبل الاستخدام الفعلي في الدائرة

- غيّر `SESSION_SECRET` إلى نص عشوائي طويل وخاص (في `.env` محلياً، وفي متغيرات البيئة على Vercel للاستضافة الحقيقية).
- غيّر كلمة مرور الحساب الرئيسي الافتراضي فور أول تشغيل.
- عند الاستضافة الحقيقية، كل البيانات (الحسابات، المهام، الصور، المرفقات) محفوظة في قاعدة بيانات Turso — يُنصح بمراجعة خيارات النسخ الاحتياطي (Backups) المتوفرة من لوحة تحكم Turso لقاعدتك دورياً.
- استضف التطبيق دائماً عبر HTTPS (Vercel يوفر ذلك تلقائياً) لحماية كلمات المرور أثناء الإرسال.
